100+ Linux-Befehle, die IT- und Security-Profis kennen sollten

Ein kompakter Praxisleitfaden für Administration, Netzwerkdiagnose, OSINT, Security-Analyse, Scripting und Systemmonitoring. Die Übersicht basiert auf dem bereitgestellten „Essential Linux Commands [+100]“-Dokument und wurde für den Blog strukturiert.

Linux ist für IT-Security, Administration und OSINT besonders leistungsfähig, weil viele Diagnose- und Analysefunktionen direkt über die Shell erreichbar sind. Die folgenden Befehle bilden einen praktischen Werkzeugkasten. Vor allem bei produktiven Systemen gilt: Befehle mit destruktiver Wirkung oder hoher Systemlast nur auf dafür vorgesehenen Testsystemen ausführen.

1. Dateien und Verzeichnisse

Die tägliche Arbeit beginnt mit Navigation, Dateisuche und Dateiverwaltung. Besonders nützlich für Analyseaufgaben sind find, file, lsof und die Varianten von ls.

ls                 # Dateien und Verzeichnisse anzeigen
ls -la             # inklusive versteckter Dateien und Details
cd /pfad            # Verzeichnis wechseln
cd ..               # eine Ebene zurück
pwd                 # aktuelles Arbeitsverzeichnis anzeigen
cat datei           # Datei ausgeben
touch datei         # Datei anlegen/aktualisieren
cp quelle ziel      # kopieren
mv quelle ziel      # verschieben/umbenennen
rm datei            # Datei löschen
find / -name datei  # nach Namen suchen
file datei          # Dateityp bestimmen
less datei          # Datei seitenweise lesen
head datei          # erste Zeilen
 tail datei         # letzte Zeilen
lsof                # geöffnete Dateien und zugehörige Prozesse

du -h --max-depth=1 # Verzeichnisgrößen
fdisk               # Partitionen verwalten

2. Verzeichnisoperationen

find / -type d -name "name"

3. Prozesse und Jobs

Für Troubleshooting und Security-Analyse ist die Prozesssicht zentral. Sie zeigt, was auf einem System tatsächlich läuft und welche Prozesse beendet oder priorisiert werden können.

4. Dateirechte und Eigentümer

chmod 640 datei
chown user datei
chgrp gruppe datei

Die Rechteverwaltung ist ein Kernbestandteil von Linux-Sicherheit. Änderungen sollten nach dem Prinzip der geringsten notwendigen Berechtigung erfolgen.

5. Netzwerkdiagnose und OSINT

Diese Befehle sind besonders relevant für Netzwerkadministration, OSINT und Security-Analysen. ss ist auf modernen Linux-Systemen in vielen Fällen die bevorzugte Alternative zu netstat.

ping host
whois domain
dig domain
netstat -pnltu
ifconfig
ip addr
ssh user@host
scp datei user@host:/ziel
wget https://example.org/datei
curl -I https://example.org
traceroute domain
mtr domain
ss -tulpn
nmap -sV host

Hinweis: Port- und Netzwerk-Scans wie nmap ausschließlich gegen Systeme durchführen, für die eine entsprechende Berechtigung besteht.

7. Textverarbeitung und Log-Analyse

Textfilter sind ein wichtiger Bestandteil der Linux-Forensik und Incident Response. Mit Pipes lassen sich mehrere Werkzeuge zu reproduzierbaren Analyseketten verbinden.

grep "pattern" datei
grep -r "pattern" verzeichnis
command | grep "pattern"
echo "text"
sed 's/alt/neu/g' datei
sed -i 's/alt/neu/g' datei
diff datei1 datei2
wc datei
awk '{print $1}' datei
cut -d':' -f1 /etc/passwd

17. Systemmonitoring und Performance

iostat
vmstat
htop
top
free -m
uptime

iostat hilft bei CPU- und I/O-Analysen, vmstat liefert Informationen unter anderem zu Prozessen, Speicher und I/O, während htop eine interaktive Prozessübersicht bietet.

18. Suche nach Programmen und Dateien

19. Datenträger und Performance-Tests

dd if=/dev/zero of=/tmp/output.img bs=8k count=256k
hdparm -Tt /dev/sda

Diese Befehle können hohe I/O-Last erzeugen. Nicht unkontrolliert auf Produktivsystemen einsetzen.

20. Gefährliche Testbefehle

Das Ausgangsdokument enthält auch Befehle, die ein System absichtlich stark belasten können, darunter yes > /dev/null & und eine sogenannte Fork Bomb. Solche Beispiele gehören ausschließlich in isolierte Testumgebungen. Sie sind nicht für Produktivsysteme geeignet.

# Nicht auf Produktivsystemen ausführen:
yes > /dev/null &
:(){ :|:& };;

Praxisregel: zuerst lesen, dann handeln

Ein sicherer Linux-Workflow besteht häufig aus drei Schritten: Zustand erfassen, Ergebnis bewerten, Änderung durchführen. Für unbekannte Befehle und Optionen ist die lokale Dokumentation die erste Anlaufstelle:

man ls
man ss
man find
man grep

Die vollständige Übersicht des bereitgestellten PDFs umfasst zahlreiche weitere Beispiele aus Dateioperationen, Netzwerkdiagnose, Git, Cron, Bash und Systemmonitoring. Die Befehle auf dieser Seite wurden redaktionell geordnet, damit sie als praktischer Blog- und Lernartikel genutzt werden können.

Security-Hinweis: Verwende Netzwerk- und Security-Werkzeuge nur auf eigenen Systemen oder mit ausdrücklicher Autorisierung. Gute Security beginnt nicht mit einem Tool, sondern mit einem klar definierten Scope.
